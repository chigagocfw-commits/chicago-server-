# apex_blips — Blip Studio

Custom map blips for FiveM, made in game. Three icon sources:

- **GTA sprite** — the full native catalogue (900+ sprites) in a searchable
  picker with real previews;
- **Image** — upload any PNG / JPG / WEBP and it becomes a *real* blip on the
  minimap and the pause map. No streaming, no YTD, no restart: the engine
  bakes the picture into a runtime texture and temporarily replaces a
  never-used DLC sprite;
- **Badge** — an emoji or up to 3 characters on a coloured disc, generated by
  the studio itself.

Every blip can carry a **map zone** (radius circle or rotated rectangle) that
optionally fires enter/exit **events**, can be visible to **everyone / given
jobs / only its creator**, supports scale, opacity, colour, category, flashing,
short-range, display mode and a **GPS route** — and the whole thing is
scriptable through **exports**.

Standalone. ESX Legacy, QBCore and QBox are auto-detected (jobs + permission
groups); with no framework it still works. Storage is `data/blips.json` — no
database.

---

## Install

1. Drop the folder in `resources/`.
2. `ensure apex_blips` in your `server.cfg`.
3. In game: `/blipstudio`.

> **Ships open to everyone.** `Config.perms.everyone = true` so you can try it
> immediately. Before going live set it to `false` — access then falls back to
> `Config.perms.groups` (`admin` by default) and `Config.perms.jobs`.

Commands (rename in `Config.commands`):

| Command | Who | What |
|---|---|---|
| `/blipstudio` | permitted | opens the studio |
| `/myblips` | anyone | hides/shows the custom blips for **yourself** only |
| `blipwipe` | server console | wipes every blip and image |

## How image blips work (and their one limit)

GTA draws every blip from **atlas sheets** inside the `minimap` texture
dictionary — individual per-blip textures don't exist. So the engine:

1. **streams a known `minimap.gfx` + `minimap.ytd` pair** (`stream/`, from
   the menkzy/fivem-blips project). That pins the sheet layout the engine
   was built against on every game build — and as a bonus your server gets
   the newest GTA Online blips. ⚠ **Streamed `.gfx`/`.ytd` only register
   after a FULL server restart** (a bare `restart apex_blips` is not enough
   the first time you install).
2. "rents" sprites nobody uses — the 14 single-player smuggler waypoints and
   27 Arena War icons (41 cells, `Config.engine.slots`, cell coordinates
   extracted from that exact `.gfx`). Each **distinct** image on screen
   takes one cell; any number of blips can share one image (40 pizzerias
   with the same logo = 1 cell).
3. re-renders the whole `blips_texturesheet_ng_2` sheet in **one DUI page**
   (vanilla art + your images in the hijacked cells) bound to a runtime
   texture (`CreateRuntimeTextureFromDuiHandle` — the pipeline our
   billboard/sign resources run in production), swaps it in with
   `AddReplaceTexture`, and pokes the radar so blips already on screen
   refresh. Every other blip keeps its vanilla pixels.

Releasing the last image restores the vanilla sheet — nothing is permanently
modified. `/blipsdebug` (F8) prints the live engine state.

⚠ If another resource streams its own `minimap.ytd`/`minimap.gfx`, one of
the two must go — duplicate streams of the same asset fight each other.
(Note: on the GTAV *Enhanced* build, streamed minimap overrides are
currently ignored by the game — classic build works.)

If some other resource on your server happens to use one of the hijacked
sprites, delete that line from `Config.engine.slots` — the engine never
touches sprites outside that list.

## Server exports

```lua
-- Create. Returns the blip id ('b_000001') or nil, reason.
local id = exports.apex_blips:AddBlip({
    name = 'Drop-off',
    icon = { mode = 'sprite', sprite = 501 },        -- or { mode='image', image=imgId }
    pos  = { x = 215.2, y = -810.1, z = 30.7 },
    scale = 0.9, alpha = 255, colour = 0,
    shortRange = true, flash = false, route = false, routeColour = 0,
    category = 1,                                     -- 1 | 2 | 10 | 11
    display  = 2,                                     -- 2 both | 3 pause map | 5 minimap
    zone = { mode = 'radius', radius = 80.0, colour = 1, alpha = 90, events = true },
    -- zone = { mode = 'area', w = 120.0, h = 60.0, rot = 45 },
    vis  = { mode = 'jobs', jobs = { 'police' } },    -- 'everyone' | 'jobs' | 'private'
})

exports.apex_blips:UpdateBlip(id, { scale = 1.2, route = true })  -- partial patch
exports.apex_blips:SetBlipEnabled(id, false)
exports.apex_blips:RemoveBlip(id)
local def  = exports.apex_blips:GetBlip(id)          -- deep copy
local all  = exports.apex_blips:GetBlips()

-- Image library (then point icons at it):
local img = exports.apex_blips:RegisterImage('Crew logo', 'data:image/png;base64,....')
exports.apex_blips:RemoveImage(img)                  -- false,'in_use' while referenced
```

Everything an export writes goes through the same sanitiser and the same sync
as the studio — partial patches are fine, unknown fields are dropped, numbers
are clamped.

## Client exports

```lua
-- Ephemeral blip for THIS player only (mission markers, deliveries…).
-- Never stored, never synced. Icons can inline a picture directly:
local id = exports.apex_blips:AddLocalBlip({
    name = 'Your delivery',
    icon = { mode = 'image', data = 'data:image/png;base64,....' },
    pos  = { x = 425.1, y = -979.5, z = 30.7 },
    route = true,
    zone = { mode = 'radius', radius = 25.0, colour = 2, alpha = 70, events = true },
})
exports.apex_blips:RemoveLocalBlip(id)

local handle = exports.apex_blips:GetBlipHandle('b_000001')  -- native handle (grab fresh, don't store)
local zhandle = exports.apex_blips:GetZoneHandle('b_000001')
local inside = exports.apex_blips:IsInZone('b_000001')
exports.apex_blips:OpenStudio()                              -- same permission gate
exports.apex_blips:Refresh()
```

## Events

```lua
-- CLIENT — fired when this player crosses a zone whose events are enabled:
AddEventHandler('apex_blips:client:zoneEnter', function(id, name) end)
AddEventHandler('apex_blips:client:zoneExit',  function(id, name) end)

-- SERVER — relayed from clients (treat as a hint, not anticheat truth):
AddEventHandler('apex_blips:zone', function(src, id, inside) end)
```

`Config.zones.events = false` switches every zone event off globally.

## Studio tour

- **Blips** — searchable list. Each row: icon, name, coords, chips
  (image/badge, zone, jobs, private, off) and actions — edit, set waypoint to
  the blip, duplicate, enable/disable, delete.
- **Editor** — icon (sprite / image / badge), identity (name, colour, scale,
  opacity), position (**my position / use waypoint / pick on map** — pick
  opens the pause map and takes the waypoint you place), behaviour
  (short-range, flashing, GPS route + colour, category, display), zone and
  visibility. On the right: a **real Los Santos map** (the same tiles as the
  apex_bossmenu tactical map) — click it or drag the marker to position the
  blip, with the zone drawn to true in-world scale.
- **Images** — the shared library. Rename, delete (refused while blips still
  use it), upload. The header meter shows image-slot usage.
- **Developer** — copy-paste export snippets that already carry the selected
  blip's id, plus full JSON export / import.

## Notes

- Blip **names** appear in the pause-map legend exactly as typed.
- **Colour** applies to sprite icons only; image icons always render untinted
  (tinting would multiply the picture with a palette colour).
- Uploads are downsized client-side to `Config.images.textureSize` (128 px)
  before they are stored or synced, so the JSON store stays small.
- After a texture swap the engine flips the bigmap for one frame so blips
  already on screen refresh immediately (`Config.engine.radarPoke`).
- The editor map needs internet on the client (tiles stream from
  gtamap.xyz, like the bossmenu map). Everything else — including image
  blips in game — is fully offline.
